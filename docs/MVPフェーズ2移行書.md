# TalkOn MVPフェーズ2移行書

## 1. 目的

本フェーズでは、TalkOnを「英会話が成立するMVP」から「会話を続けたくなり、終了後に具体的な学びを得られるMVP」へ移行する。

対象は次の3点である。

1. AIとの会話を、固定的な質問応答から文脈に沿った自然な会話へ改善する
2. 長い会話でも、入力欄付近から会話を終了できるようにする
3. 会話内容に応じて、文法以外も含む柔軟で具体的なフィードバックを返す

## 2. 調査範囲

次の処理を、画面からAI呼び出しと保存まで追跡した。

- `frontend/src/App.tsx` の会話画面と終了操作
- `backend/src/main/java/com/kazuto/talkon/conversation/ConversationService.java` の履歴取得とAI呼び出し
- `backend/src/main/java/com/kazuto/talkon/llm/AiClientConfig.java` のローカルAI・OpenAI互換API実装
- `backend/src/main/java/com/kazuto/talkon/llm/Prompts.java` の会話・フィードバック指示
- `backend/src/main/java/com/kazuto/talkon/feedback/FeedbackGenerationService.java` の生成・検証・再試行
- `backend/src/main/java/com/kazuto/talkon/feedback/FeedbackData.java` のフィードバック構造と入力検証
- フロントエンドおよびバックエンドの関連テスト

## 3. 調査結果と原因

### 3.1 会話が不自然になる原因

#### 原因箇所

`backend/src/main/java/com/kazuto/talkon/llm/AiClientConfig.java` の `LocalAiClient.reply()` が主な原因だった。

APIキーが設定されていないローカル環境では、READMEの仕様どおり外部LLMではなく `LocalAiClient` が使われる。修正前の応答は次の3質問をターンごとに切り替える方式だった。

- `How did that make you feel?`
- `What happened next?`
- `Would you like to do that again?`

ユーザーの発言内容を応答生成に利用していなかったため、話題と質問が一致せず、同じ会話パターンが繰り返されていた。

OpenAI互換APIを使う場合は直近20メッセージが渡されており、履歴欠落は発生していなかった。一方、`backend/src/main/java/com/kazuto/talkon/llm/Prompts.java` の指示は「自然に会話する」という抽象的な内容が中心で、最新発言の具体的な情報をどう拾うか、新しい話題を一度にいくつ導入するかが明確ではなかった。

#### 今回の対応

- `LocalAiClient.reply()` が直近のUSERメッセージを読み、疲労、散歩・ハイキング、食事などの話題へ応じて反応を変えるようにした
- 質問だけを返し続けず、共感や短い関連コメントを含めるようにした
- レベル別に文の長さと表現を変える既存方針を維持した
- 会話プロンプトへ「最新発言の具体的な情報を拾う」「過去文脈へ接続する」「新しい話題は一度に一つ」「一般的な褒め言葉より関連する反応を優先する」を追加した

### 3.2 会話終了ボタンへ戻りにくい原因

#### 原因箇所

`frontend/src/App.tsx` の `ConversationPage` では、終了ボタンが `.conversation-head` 内に一つだけ存在していた。メッセージ数が増えると、ユーザーは画面上部までスクロールしなければ終了できなかった。

入力欄は `frontend/src/styles.css` で画面下部へsticky表示されているが、入力欄周辺には終了操作がなかった。

#### 今回の対応

- 既存の上部終了ボタンは維持した
- sticky入力欄の直下へ、同じ `finish()` を呼ぶ下部終了ボタンを追加した
- 送信または終了処理中は、上下どちらの終了ボタンも無効になる既存の `busy` 制御を共用した
- 上下に2つの終了導線が表示され、下部ボタンから終了APIを呼べるコンポーネントテストを追加した

### 3.3 フィードバックが定型的になる原因

#### 原因箇所

最大の原因は `backend/src/main/java/com/kazuto/talkon/llm/AiClientConfig.java` の `LocalAiClient.feedback()` だった。

修正前は、最初のUSERメッセージだけを調べ、文字列が `Today is tired.` と完全一致した場合だけ訂正していた。それ以外では、会話内容や発言数に関係なく同じsummary、strengths、vocabularyTips、overallCommentを返していた。

外部LLM向けの `Prompts.FEEDBACK` もJSON形式と件数制限は定義していたが、次の判断基準が不足していた。

- 会話全体の文脈を評価すること
- 実際のUSER発言だけを引用すること
- 文法的に正しくても不自然な表現を必要に応じて扱うこと
- 学習効果の高い指摘を優先すること
- summaryや良かった点を会話固有の内容にすること

`FeedbackData` は複数カテゴリと最大5件の訂正を保持できるため、データ構造やDBが定型化の原因ではなかった。

#### 今回の対応

- 外部LLM向けプロンプトへ、会話全体の評価、原文引用、優先順位、自然さ・語彙の指摘、具体的な日本語説明を追加した
- ローカルAIも全USERメッセージを対象にし、複数件の訂正を返せるようにした
- ローカルAIで `I am agree` の文法指摘と `I very like` の自然さ指摘を追加し、カテゴリの異なる指摘ができるようにした
- summaryへ直近の話題と発言数を反映し、訂正の有無によってoverallCommentを変えるようにした
- 異なる2種類の誤りと会話固有summaryを検証する単体テストを追加した

## 5. 修正後の処理

### 5.1 会話応答

```text
直近20メッセージ + 英語レベル + 会話ルール
  ↓
最新発言の具体的な話題へ反応
  ↓
必要な場合だけ、関連する質問を一つ返す
```

APIキーがない場合も、ローカルAIが直近発言のキーワードを使って応答を切り替える。ただしローカルAIは開発・動作確認用であり、任意の話題を理解する汎用LLMではない。

### 5.2 会話終了

```text
上部ボタン または 入力欄下のボタン
  ↓
共通の finish()
  ↓
POST /api/conversations/{id}/finish
  ↓
会話をENDEDへ変更し、フィードバック生成へ移行
```

### 5.3 フィードバック

```text
会話内の全USERメッセージ
  ↓
会話内容、伝達できた点、改善効果の高い表現を分析
  ↓
文法・語彙・自然さ・語順から最大5件
  ↓
既存のBean Validationを通過した結果だけ保存
```

## 6. MVPフェーズ2の制約

- ローカルAIは決定的な開発用実装であり、登録済みの話題・誤りパターン以外を深く分析できない
- OpenAI互換API利用時の品質は、設定モデル、APIの可用性、プロンプト追従性に依存する
- 現在は会話ごとの目的、場面、AIの人物設定をユーザーが選択できない
- フィードバックの正確性を人手評価する品質指標や評価データセットはまだない
- 直近20メッセージより前の内容は、長い会話ではAI入力から外れる
- 下部終了ボタンは入力欄付近に表示されるが、誤操作確認ダイアログは設けていない

## 7. 次フェーズ案

### 優先度A: 品質を測定可能にする

1. 会話・フィードバックの匿名化評価データセットを作成する
2. 「文脈整合性」「質問の重複」「レベル適合」「訂正の正確性」「具体性」を採点する自動評価を追加する
3. ユーザーがAI応答とフィードバックを役立った・役立たなかったで評価できるようにする
4. プロンプトとモデル名をバージョンとして会話に記録し、品質変化を比較できるようにする

理由: 自然さはテスト成功だけでは保証できない。改善前後を同じ会話例で比較できる基盤を先に作る必要がある。

### 優先度B: 会話体験を個別化する

1. 旅行、仕事、日常、面接などの会話シナリオを選択可能にする
2. 会話開始時に目的と話したい話題を入力できるようにする
3. レベルだけでなく、応答速度、文の長さ、質問頻度を調整可能にする
4. 長い会話では、古い履歴を要約して直近履歴と一緒にAIへ渡す

### 優先度C: フィードバックを練習へ接続する

1. 指摘ごとに「この表現を練習する」導線を追加する
2. 過去に繰り返した誤りをユーザー単位で集計する
3. 次の会話で過去の課題を自然に再出題する
4. フィードバックの指摘について、理由の追加説明や例文を質問できるようにする

### 優先度D: 安全性と運用品質を上げる

1. 会話・フィードバックのモデレーション方針を定義する
2. 外部LLMのタイムアウト、レート制限、JSON不正応答をメトリクス化する
3. モデル更新時の回帰評価をCIへ追加する
4. コスト、応答時間、失敗率をモデル・プロンプトバージョン別に監視する

## 8. 次フェーズ移行条件

次フェーズへ進む前に、最低限次を満たすことを推奨する。

- 代表的な会話シナリオを10件以上用意し、改善前後を比較できる
- 同じ質問の不自然な反復を自動検出できる
- フィードバックの原文が実際のUSER発言に含まれることを検証できる
- 文法的に正しい英文へ不要な訂正を行わないことを人手サンプルで確認する
- 会話終了操作が長い会話とモバイル幅の両方で利用できる
